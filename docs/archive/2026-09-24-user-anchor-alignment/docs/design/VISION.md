# Game vision

Status: working product brief, consolidated 2026-09-24. Existing direction and
the user's current quality objectives are distinguished below. Detailed mechanics
live in [the current mechanics map](MECHANICS.md); future ideas live in
[possible routes](POSSIBLE_ROUTES.md).

## Core concept

Build a collection of real gemstones, use its interactions to solve constrained
merge boards, carry selected investments forward, and extract a flagship gem.
The intended satisfaction combines shaping a build with placing its pieces well:
“that combination made my build work” and “I put the survivor in the right place.”

The user has asked for realistic-looking gemstone animations made with the
existing asset engine, a cohesive artistic vision, and substantially better UI,
sound, environment art and interaction. Existing presentation choices are open
to redesign. Dependable implementations and core concepts should survive where
they serve that experience.

## Working pillars

These synthesize the earlier design direction; they guide exploration but do not
preselect a visual setting or composition.

1. **Readable decisions.** Show what can be acted on, what it will cost, where a
   survivor will be, and why a family reaction or objective event occurred.
2. **Investment matters.** High-tier pieces occupy valuable space and can be
   carried or delivered. Their identity and fate should be understandable.
3. **Build and board reinforce each other.** Rewards should alter useful spatial
   decisions. Family effects need purposeful setups and intelligible limits.
4. **Pressure has boundaries.** Work constrains a room; equilibrium allows
   deliberation. Current merge windows add optional paid intervention opportunities.
5. **Convincing gemstones, fictional game rules.** Material appearance has
   provenance. Matching, appraisal bands and abilities are authored game systems.
6. **Production serves play.** A striking isolated render is insufficient if the
   stone is unreadable or distracting on the board. The environment and sound
   should support the same experience.

## Scope to carry into exploration

The current baseline is a desktop, single-player, three-room expedition with
eight active tiers and the Aquamarine replacement, three implemented families,
rubble and delivery objectives, tools, two settings, rewards and selective carry.
Maintain that playable scope while establishing the presentation direction.

The inherited 10–15 minute run length is a hypothesis, not measured pacing or a
requirement to rush decisions. Windows is the existing verified target; mobile
and a six-room expansion are later options. The current run ends on failure and
can be restarted; combat, monetized rescue moves, extra currencies and permanent
stat grind are not part of this prototype brief.

## Design freedom

The former jeweler's-workshop palette, panels, layout, vector rubble, procedural
background and synthesis recipes are prior proposals. They are available as one
candidate direction; they are not requirements for every alternative.

Preserve meaning and readability while exploring composition, spatial metaphor,
hierarchy, interaction, material treatment, typography, sound and motion. A
different theme is not automatically better. A familiar element can survive
when it earns its place in the chosen experience.

Gem realism does not require every UI element or environment to be photorealistic.
The relationship between realistic gems and their surroundings is a design
question to demonstrate. Do not equate quality with maximal effects, permanent
gem motion, more features or a larger asset catalog.

## User authorship

[User anchors](USER_ANCHORS.md) provides space for fantasy, references, constraints
and consequential choices. Unanswered fields remain open. Agents should expose
alternatives and tradeoffs through concrete studies rather than filling the
blanks with invented user preferences.

Ask focused questions when a consequential ambiguity blocks a decision. Continue
independent investigation and reversible studies meanwhile. Record confirmed
choices there, then update the owning brief; do not quietly elevate suggestions
or historical choices into new approvals.
