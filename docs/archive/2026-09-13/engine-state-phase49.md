# Foundation acceptance review, phase 49 (pending integrated completion)

The engine now has a coherent physical-condition authoring path in addition to transport, geometry, materials, style and delivery. This closes the disconnected-grading-demo problem: named presets realize ordinary inspectable specimens before rendering. Enabled study mechanisms are explicit finish/rounding, manufacturing tolerance, localized scattering and foreign crystal populations. They are authored physical states, not measured natural grade classes. Automatic fracture generation remains off after failed visual morphology review. At 512px, narrow softened highlights retain sampling noise; at production112px the measured two-stream RMS is .393-1.032LSB for softened polish and .216-.342LSB for the localized cloud. These are conditional observations, not guarantees for every material/shape/lighting combination.

Supported mechanisms have independent numerical, geometry and practical render checks. Physical catalog inputs carry evidence classifications. Specialized biaxial, anisotropic silk, fluorescence and structural-color mechanisms remain outside validated transport rather than being faked by a mineral-name switch. The architecture can accept new materials, spectral data, cut programs, analytic/general shapes and explicit conditions without adding a bespoke tile renderer. Adding a mineral is data authoring within a declared supported physical model; it is not a promise that every optical phenomenon follows automatically from its name.

Asset production uses requested animations and explicit rigs, preserves optical masters for reprinting/resizing/restyling, freezes jobs in portable independent Godot projects, supports caching/resume/shards/transfers, and ships only referenced compressed pages. The game consumes metadata and selective bounded pages; no runtime bake is required. Local Windows independent bundles are validated; actual Linux/network-FS/farm execution remains deployment work, not an untested supported claim.

One concrete workflow gap remains before final foundation delivery: the convenience planner selects one quality preset under a base stone ID. Low-level arbitrary jobs/clips already support multiple variants, but a first-class explicit request collection should make simultaneous quality/lighting variants accessible without hand-building dictionaries. This is a planner/data change only. See artifacts/specimen-study/delivery-planning-gap.md. Add it, validate actual portable multi-variant results, then restore/build the full catalog, fresh-cache replay and board check. Avoid another unchanged numerical detour or repeated fullsuite absent new optical changes.
